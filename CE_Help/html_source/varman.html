VarMan Overview

VarMan is a variable manager that provides LabVIEW applications with the ability to dynamically create, read, write, and manage data. VarMan variables can be used to store and share data within application code, as well as share data with CalcExpress and CSE scripts.

Variables are stored and operations on variables are performed by the VarMan Engine. CalcExpress and CSE have direct access to the VarMan Engine and can manipulate variables and their properties within processed scripts.

To work with variables in applications, there is a set of VarMan VIs which interact with the VarMan Engine and give applications full control over variables and their properties. See the VarMan VIs topic for details.

To simplify the debugging process for complex applications, the VarMan Spy utility is available. This tool investigates and manages VarMan variables.

    A VarMan variable acquires its core properties upon its creation. Some core properties, like Variable Context, Name, and Data Type, remain constant throughout a variable's lifetime. Variable Value and Writer ID properties alter every time a variable is written.The Variable Context and Name properties distinguish a variable from other variables. Data Type and Value properties determine the data stored in the variable. By default, variables do not have any on-demand properties; they are assigned explicitly when requested.

    Topics below describe the variable properties in detail.

     

    Variable Context

    VarMan stores variables in variable contexts. VarMan supports up to 65,535 independent local contexts, as well as a global context. Each context has its own namespace for variables, preventing conflicts between variables with the same names across different contexts.

    To access a variable context, a context handle (VC handle) is used. When VarMan opens a local context, it returns a context handle that must be used for all operations involving the context and its variables. Optionally, a unique context name can be assigned to a local context for convenient reference. VarMan uses a global namespace for context names which does not interfere with other namespaces; therefore, context names do not conflict with variable names or aliases.

    A newly opened local context does not contain any variables. When a local context is closed, all variables within it are automatically destroyed. The global context exists by default and does not need to be opened or closed. To close all local contexts and clear the global context, the VarMan initialization VI can be used.

     

    Variable Name

    VarMan distinguishes variables by their names. Each variable name is unique within the variable context it exists. However, variables with the same name may exist independently in different contexts. Thus, the combination of a variable name and context handle uniquely identifies the variable.

    There are the following rules for naming variables:

    • a variable name may consist of alphabetic characters (upper- and lower-case letters), decimal digits, and underscores ( _ ).
    • the first character of a variable name must not be a digit.
    • a variable name is case-sensitive; lower-case and upper-case letters are treated as distinct characters.
    • there is no limit on the length of a variable name, and all characters are significant.

    To access a variable, VarMan searches for the variable name in the local context using the provided context handle. If the variable is not found, VarMan searches the global context, unless this behavior is explicitly suppressed. Consequently, local variables hold higher priority than global variables.

     

    Variable Data Type

    Data type describes the format of data stored in a variable. VarMan supports all predefined data types that CalcExpress supports. Additionally, it supports any user-defined data type whose values are represented in the Flattened-To-String format. See the Data types topic for more information.

     

    Variable Value

    Variable values can be manipulated using VarMan VIs, as well as within CalcExpress and CSE scripts. The variable value must match its declared data type. VarMan and CalcExpress automatically verify this condition for all predefined data types.

     

    Writer ID

    The Writer ID is a numeric identifier updated every time a value is written to a variable. The primary purpose of the Writer ID is to track the source of variable values. It allows applications to:

    • Track and distinguish sources across parallel loops or separate scripts (e.g., which thread or VI updated this setpoint?).
    • Track specific execution points within complex scripts where a variable is written (e.g., did step 4 or step 12 write this value?).

    The Writer ID is an unsigned 32-bit integer that can hold an arbitrary value. An application can utilize custom predefined codes for this identifier, or cast VI references to it. If an identifier is not explicitly specified via VarMan VIs, CalcExpress, or CSE scripts, a default value of 0 is automatically applied.

    VarMan VIs feature paired inputs for both the Variable Value and the Writer ID to write them together.

    In script processing, CalcExpress and CSE engines update the Writer ID automatically when a variable is written. The identifier used by a script instance can be defined before script execution starts using relevant CalcExpress or CSE VIs, or altered during script processing using the vwrid() function. The Writer ID for the most recent value of any variable can be read using the vstwid function, and the Writer ID of a variable's creator can be read with the vstcid function.

     

    Alias

    An alias is an optional identifier that can be associated with a variable. Aliases serve as an alternative way to refer to their associated variables. VarMan uses a global namespace for aliases that does not interfere with other namespaces; therefore, aliases do not conflict with variable names or context names. Each alias is unique within the entire VarMan framework, whereas a variable name is only unique within the context in which it exists. This feature allows an alias to access the associated variable without needing to know its name or context handle. For more information on using aliases, see the Referring to Variables topic.

     

    Variable History

    Optionally, VarMan can maintain a history of specified variables. The variable history accumulates the values assigned to a variable during its lifetime, along with timestamps and Writer IDs indicating when and where those assignments occurred, providing a complete execution audit trail. See the Variable History topic for more information.

     

    Variable Attribute

    The variable attribute is an optional parameter that can be used to store arbitrary data associated with a variable. A variable attribute can be read and written using the VM - Variable Attribute.vi.
