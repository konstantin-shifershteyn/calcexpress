Data types in CalcExpress, CSE and VarMan

There is a set of native data types in CalcExpress, CSE and VarMan (which are referred to as predefined data types). In addition, they can handle custom data types if you need to work with your own types of data (user-defined data types). This topic provides information on the predefined data types and guidelines for using custom data types.

  • user-defined data types

Predefined data types

Predefined data types are listed in the table below. Data types can be divided into two categories: Basic and Complex (you can meet these terms in CalcExpress descriptions and messages). This division exists because there are some differences in how CalcExpress and VarMan handle data. The most significant difference is how CalcExpress passes parameters to and from FuncVI functions. Values of the Basic data types are passed in the LabVIEW's native representation, while values of the Complex data types are passed in the Flattened-To-String format (see help for the Flatten To String and Unflatten From String LabVIEW functions for details).

Identifier data type

Typically, the Identifier data type is only used inside CalcExpress. It specifies that an operand is either a variable name or a function name. However, it is possible to use this data type in some advanced scenarios; e.g., indirect function calls.

 

IndexRange data type

The IndexRange data type is only used inside CalcExpress to define a range of array element indexes in the Subscript operator. This data type is produced by the IndexRange operator, IndexRange Symbols, and Index Range functions.

The IndexRange data type specifies a sequential range of indexes from an initial boundary up to a final boundary. If the initial boundary of a range is less than the final boundary, the index range is incremental with the step of 1; otherwise, the index range is decremental with the step of -1. The boundaries are integers and can have values between 0 and 231-1. If a boundary is out of this range, it is coerced to zero (0).

If you use an IndexRange operand as an index in the Subscript operator, CalcExpress adjusts the boundaries of the index range to match the array size (dimension size for 2D arrays). Note that the maximum array index is one less than the array size (dimension size).

Operands of IndexRange dat type are produced by IndexRange Operator, IndexRange Symbols, and IndexRange Functions.

Examples

0:5 /* index range from 0 up to 5 */
10:1 /* decremental index range from 10 to 1 */
2:2 /* index range consist of only single index 2 */
-10:5 /* index range from 0 up to 5 */
-5:-5 /* index range consist of only single index 0 */
$> /* index range from 0 up to a maximum possible value */
$< /* decremental index range from a maximum possible value to 0 */
5:$>/* index range from 5 up to a maximum possible value */
$<:3/* decremental index range from a maximum possible value to 3 */

 

User-defined data types

In general, CalcExpress, CSE and VarMan allow you to operate on data of arbitrary data types. To do this, you need to represent your data in the Flattened-To-String format and associate a unique datatype code with your data. Choose a datatype code for your data from the following ranges: from 128 up to 249, or from 1000 up to 9999.

(*) Use the Flatten To String and Unflatten From String LabVIEW functions to convert data to/from the Flattened-To-String format.

VarMan specifics

To manage variables of arbitrary data types in your applications, use the VM - Arbitrary Data.vi. You can use it directly, or create a wrapper VI around it for each data type you use, which can be more convenient.

CalcExpress and CSE specifics

CalcExpress has access to variables within the VarMan Engine regardless of their data types. If you create a variable with an arbitrary data type (using the VI mentioned above), you can access it in CalcExpress expressions and CSE scripts. Although most operators and all embedded functions can operate on the predefined data types only, you can manipulate an arbitrary data in expressions/scripts. Consider the following features:

  • CalcExpress validates the data type of an operand only if it needs the operand value to perform either an operator or an embedded function. However, there are a few operators that do not care about operand data types; these are the comma, semicolon, and bracket operators.
  • Both Equality and Inequality operators only require that operands have the same data type. They can be used to compare operands of any data types.
  • The Assignment operator only requires that both operands have the same data type. It can be used to assign a value to variable of any data type, providing that the data types of the variable and the new value match.
  • CalcExpress does not check the data type of function arguments when calling a FuncVI function. A FuncVI is able to accept arguments of any data type, and if necessary, it can validate the data types of these arguments.
  • CalcExpress does not check the data type of the value returned by a FuncVI function until that value is used to perform an operator or call an embedded function. A FuncVI can return a value of any data type.

Thus, in order to process data of an arbitrary data type in CalcExpress expressions or CSE scripts, you need to create a set of FuncVI functions that can recognize and handle such data.
