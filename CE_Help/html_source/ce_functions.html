Functions in CalcExpress and CSE

Functions are used in CalcExpress and CSE scripts to perform specific tasks. CalcExpress has a large set of predefined functions, as well as the ability to create and use custom functions.

The distinguishing feature of a CalcExpress function is its implementation. There are two methods of implementation: FastFunc and FuncVI. The FastFunc method is used for implementing predefined functions only. The FuncVI method can be used to implement both predefined and user-defined functions. If you need a new function, create a VI named FuncVI and use it like any other predefined function. Since a FuncVI is a VI, you can use all LabVIEW features for implementing your functions.

CalcExpress provides a uniform syntax for function calls regardless of a function implementation. The syntax allows calling a function that processes an arbitrary set of arguments and returns an arbitrary value (both values and datatypes should be considered under this statement). This means that CalcExpress supports polymorphic functions as well as polymorphic operators. Many of the predefined functions are polymorphic.

Function Call Syntax

The syntax of a function call is the same for all functions, regardless of the function implementation. A function call has the following form:

funcname ( arguments-list )

, where

funcname is a name of the called function (function name).
argument-list is a list of arguments passed to the function (argument list).

 

Function name

A function name consist of alphabetic characters, digits and the underscore characters, but the first character is not a digit. Case sensitivity of a function name depends on the implementation of that function. FastFunc functions have case-sensitive names, while FuncVI functions have case-insensitive names. Many predefined functions have both FastFunc and FuncVI implementations. This rule of case sensitivity makes it possible to choose the desired implementation of a predefined function to perform the function.

Example:

y = sin(x);  /* sin(x) is call of FastFunc function */
y = Sin(x);  /* Sin(x) is call of FuncVI function   */
y = SIN(x);  /* SIN(x) is call of FuncVI function too */

Function names do not conflict with variable names. This means that a variable can have the same name as a function. CalcExpress differentiates between a function name and a variable name depending on the context it is met.

Example:

max = 0;          /* max is variable */
x = max(-1,2);    /* max is function name */
max = max(x,max); /* variable max equals 2 */

 

Argument list

An argument list may contain any number of arguments, with no restrictions. If there are two or more arguments, they are separated by commas. Commas within string constants, character constants, comments, or nested parentheses are ignored. If an argument is an expression involving the comma operator, put it within parentheses.

Example:

/* after code avaluation, s will be equal "x=0.250, x/erf(x)=9.04727E-1" */
x=.25;
s=sform("x=%.3f, x/erf(x)=%.5e", x, (y=erf(x), x/y));

In general, an argument is any expression, such as a constant, a variable, or an expression that involves operands, operators, or function calls. CalcExpress passes arguments to functions by value (except for variables) and evaluates them before calling the function. The arguments are evaluated, including any side effects, in the order they appear in the function call.

Example:

/* after code evaluation, y equals 125, and x equals 5 */
x=4;
y=pow( x+=1, x-2 );

If an argument is a variable name (identifier), it is passed to a function as-is. A function receives the variable name as an input parameter; in this way, the function can evaluate the value of the variable or/and assign a new value to it.

CalcExpress has no syntax restrictions on the number of function arguments, argument data types, and a return value. CalcExpress calls a function without checking the amount and data types of arguments. If all the arguments in a function call are successfully evaluated, CalcExpress passes them all to the function.

When a function is called, it receives both argument values and their data types. The called function verifies the passed arguments and decides whether they are valid, i.e., whether the function can use the arguments to perform a specific task.

 

Return value

Every function returns a value. The return value and its data type are determined by the function itself. The data type of the return value can be either constant or dependent on the data types of the arguments passed to the function.

 

 

 

Functions Implementation

CalcExpress uses two kinds of function implementations: FastFunc and FuncVI. Both methods are used to implement predefined functions but only the FuncVI method can be used to implement user-defined functions.

FuncVI functions

The FuncVI method allows using a custom VI (referred to as a FuncVI) to implement a script function. Because a FuncVI is a standard LabVIEW VI, you can utilize any native LabVIEW functions and VIs to implement custom routines of any complexity.

CalcExpress utilizes dynamic calls to load FuncVIs. None of the core CalcExpress VIs contain FuncVIs in their hierarchy; instead, the engine loads only those specific FuncVIs required to process the active script.

CalcExpress automatically loads the required FuncVI into memory at runtime if it is not already present. Furthermore, you can forcefully pre-load a FuncVI before starting script execution to eliminate the overhead of loading it during the first function call. Use Func - Load Functions.vi to programmatically load FuncVIs at runtime. Alternatively, you can force LabVIEW to load a FuncVI into memory by dropping a Static VI Reference to it onto your application's block diagram.

To determine which FuncVI needs to be executed, CalcExpress resolves the function name dynamically. If the script engine encounters a function call that does not correspond to a built-in core function (FastFunc), it attempts to locate and execute a matching FuncVI on disk. CalcExpress searches for the appropriate file based on the function name and then runs it dynamically. Note that CalcExpress cannot determine if a function name is valid until it actually attempts to locate and call the corresponding FuncVI. Search paths are managed via Func - FuncVI search paths.vi.

When building a standalone application (EXE), you must ensure that CalcExpress can successfully open VI references to used FuncVIs at runtime. The easiest approach is to include them directly inside your compiled executable file. It can be achieved either by using Static VI References to necessary FuncVIs or by including them in your application's project file ("Always Included" list). A more advanced but flexible method is to store your FuncVIs in separate external directories or LLB libraries; this allows you to update or expand your script vocabulary without rebuilding the core application binaries. However, if you store them externally, you must be careful to preserve the entire sub-VI dependency hierarchy when distributing your application.

 

FastFunc functions

The FastFunc method is used to implement both built-in functions and operators. FastFunc functions are a native part of the CalcExpress Engine DLL; they do not require any external VIs because they are executed directly inside the compiled CalcExpress kernel.

Consequently, FastFunc functions are faster (often significantly faster) than FuncVI functions.

CalcExpress recognizes FastFunc function names during the parsing phase. If a function call matches a recognized FastFunc function name, the engine executes it natively; otherwise, CalcExpress attempts to locate and perform a FuncVI function instead.

To retrieve the complete list of available FastFunc functions, you can call the _fflist function within a script. This function returns a spreadsheet string containing the name and the number of expected arguments for every FastFunc function.
