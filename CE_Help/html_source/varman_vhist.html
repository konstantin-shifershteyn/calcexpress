Variable History

A variable history records the values assigned to a variable, along with the timestamps of when each assignment occurred.

VarMan transparently handles variable histories. You should only declare a history for a desired variable, and then VarMan will automatically manage the variable history according to the parameters you specify. VarMan can handle history for variables of any data type, both predefined and user-defined.

VarMan uses a circular buffer technique to maintain a variable history. At any time, the history contains as much recent data as can be accommodated within it, depending on the size of the history you specify.

Creating history

By default, VarMan does not save historical values of variables. To activate this feature, you need to explicitly instruct VarMan to create a history, and configure its parameters. Use VHistory - History Controller.vi to create and configure variable histories.

When you create a variable history, you must specify the history length, which is the maximum number of values that can be saved. The circular buffer technique is used to save the most recent data. Additionally, you can set optional time and value conditions to influence how the history is handled. Note that while it is possible to reconfigure the time and value conditions for an existing history, the history length cannot be changed.

IMPORTANT: Note that a large history length can lead to a significant increase in memory usage, especially if a variable is an array.

 

Destroying history

VarMan automatically destroys a variable history when the respective variable is destroyed. You can also explicitly destroy a history if you no longer need it or if you want to recreate it with a different size. Use VHistory - History Controller.vi to destroy a variable history.

 

Updating history

Every time a value is assigned to a variable, either during script processing or with a call to VarMan VI, VarMan saves the value in the variable history unless any configured condition suppresses this. If the history buffer is full, VarMan overwrites the oldest value with the newest one.

VarMan uses two kinds of conditions to decide whether the history needs to be updated, and a way for doing so.

Time conditions

Time Step condition. If  CurTime-LastTime >= Step,  VarMan adds a new record to the variable history; herewith it does not check other conditions.

Time Gate condition. If  CurTime-LastTime < Gate,  VarMan overwrites the last stored value with the new value (hereby it keeps the respective time stamp unchanged) unless other conditions are met. VarMan does not check this condition if the Time Step condition is already true.

, where

CurTime is the current time (timestamp when the value assignment occurs).

LastTime is a timestamp of the last value stored in the history.

The Step and Gate are number of milliseconds specified as time conditions in VHistory - History Controller.vi. By default, both are equal to zero.

Value condition

A value condition, if met, causes VarMan to add a new record to the history. Note that a value condition only makes sense if the Time Step condition is specified; i.e. if the Step parameter is greater than zero (see the Time conditions topic above). VarMan will not check a value condition if the Time Step condition is already true.

Supported value conditions are listed below. Note that the changed condition can be applied to variables of any data type, while all other conditions apply only to DBL scalars.

changed condition is met if
      NewVal != LastVal (not equal)

abs deviation condition is met if
      |NewVal - LastVal| >= |Delta|

rel deviation condition is met if
      |NewVal - LastVal| >= |LastVal * Delta|

out of range condition is met if
      NewVal <= RangeMin  OR   NewVal >= RangeMax

within range condition is met if
      NewVal >= RangeMin  AND  NewVal <= RangeMax

, where

NewVal is the new value assigned to the variable.
LastVal is the last value stored in the variable history.
The Delta, RangeMin and RangeMax are parameters specified as part of a value condition in VHistory - History Controller.vi. By default, they are all equal to zero.

IMPORTANT NOTICE

In CalcExpress and CSE scripts, VarMan does not update the variable history if a value is assigned to an indexed variable; i.e., a variable name followed by a index expression is situated as the left-hand operand of the Assignment operator.

Example

for(i=0; i<10; i+=1) {
  /* this assignment does not cause a history update */
  array[i] = i*5;
}
/* the statement below causes an updating of the history of array */
array = array;

/* the statement below has same effect as the statement above */
array += 0;

 

 

Reading history

If a variable has a history, it can be read using Variable History VIs. There is a dedicated history VI for each predefined data type. In addition, there is a VI that returns history values of an arbitrary data type in the Flattened-To-String format. Every VI returns a variable history in two arrays: an array of variable values and an array of timestamps. A timestamp is a DBL number representing date and time in the LabVIEW date/time format.

VarMan VIs provide a few ways to read historical values:

  • By default, you can read entire history.
  • Using TimeRange mode, you can read historical values with timestamps within a specified time range.
  • Using N-Vals mode, you can read the specified number of the newest values saved in a history.
  • Using NewVals mode, you can force VarMan VIs to return only the newest values saved to history since the last reading of the history was done in this mode. NewVals mode can be especially useful if you need to write historical values to log files asynchronously with other parts of an application (see History Log File VIs).
