Non-Fatal runtime errors

Within every variable context there is a hidden variable (called the rtErrorCode) to keep code of runtime errors that don't cause a CalcExpress error. CalcExpress VIs use this variable to store execution status of some functions; typically, it is LabVIEW error code. For instance, if a FuncVI function uses a LabVIEW VI that returns an error code (through either digital error indicator or error cluster), it assigns the LabVIEW error code to this variable when it is completed.

Although it is impossible to directly access rtErrorCode you can both evaluate it and assign a value to it in a script with the help of errno function. CalcExpress VIs never change a value of rtErrorCode unless they perform a function that does it. Refer to a function description to learn whether the function changes rtErrorCode value.

Due to the fact rtErrorCode is kept within a variable context, a few CalcExpress instances use the same rtErrorCode if they operate on the same variable context. The advantage of this is possibility to use rtErrorCode in CSE scripts when it is assigned and evaluated sequentially by different CalcExpress instances. However you should be careful if you evaluate rtErrorCode in CalcExpress VIs, which simultaneously work on the same variable context.

To access rtErrorCode in a script, use errno, lvErrorMessage, or lvErrorString functions.

If you need to assign a value to rtErrorCode in a FuncVI you develop, use Func-LV runtime error code.vi
