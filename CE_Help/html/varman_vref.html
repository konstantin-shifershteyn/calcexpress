Referring to variables

VarMan supports two methods to refer to a variable: by using its name or by using an alias associated with it. Many VarMan VIs have a control called name_spec. To refer to a variable, a proper name specifier must be passed to the name_spec control. Also, if a variable is referenced by name, a handle of the context where the variable exists (or should be created) must be provided.

Generic format of a name specifier (name_spec):

[name][=alias]

, where

  • name is an identifier that specifies a variable name. It can consist of letters, digits, and underscores; the first character must not be a digit.
  • equality mark ( = ) indicates that an alias follows. Spaces are not allowed between the equality mark and a name or alias.
  • alias is an arbitrary string that may consist of characters with codes greater than or equal to 0x20 (space mark), but the space mark must not be the first or last character. VarMan treats a string after the equality mark as an alias.

Either name or =alias can be omitted in name_spec, but not both.

 

 

Use cases while operating on existing variables

An existing variable can be referred to using its name or an alias, if one has been associated. The following patterns show how to do this.

 

name_spec is like either "name" or "name=alias"

If the first character in a name specifier is not an equality mark, VarMan will treat all characters up to the end of string or before an equality mark (if any) to be a variable name. In this case, VarMan ignores alias (if any) and performs an operation on the variable with the specified name in the specified context.

name_spec is like "=alias"

If the first character in a name specifier is an equality mark (i.e. a name is omitted), VarMan interprets the rest of string as an alias. In this case, it performs an operation on the variable that is associated with that alias. There is no need to specify a context handle (any value will be ignored), VarMan will take it from the alias' record.

 

 

Use cases while creating variables

When you create a variable, you can optionally associate an alias with it (if needed, an alias can be associated later with the help of VM - Alias Controller.vi). When creating a variable, you must always explicitly specify the variable context where the variable is to be created.

The following patterns show how to create variables and aliases.

 

name_spec is like "name"

If a name specifier contains only a variable name (there is no equality mark), VarMan creates a variable with that name in the given context, but does not associate any alias with it.

name_spec is like "name=alias"

If a name specifier contains both a variable name and an alias (there is an equality mark in any position except the first one), VarMan creates a variable with the specified name in the given context and associates the specified alias with it.

name_spec is like "=alias"

If a name specifier contains only an alias (the first character is an equality mark), VarMan creates a variable with a randomly generated unique name in the given context and associates the specified alias with it.

 

 

Using aliases in CalcExpress and CSE scripts

In order to use aliases in scripts, there are CalcExpress functions designed to manage variables. These functions accept a variable name as a string parameter and can work with aliases, according to the "Referring to Variables" rules described above.

Example

/*****  It is CSE Script *****/
alias = "Test Tag #1";     /* alias associated with a desired variable */
nspec = scat("=", alias);  /* name specifier equals "=Test Tag #1" */

/*
Test if the alias exists and associated variable has dbl scalar type
it's required to prevent a run-time error that may occur otherwise
*/
if (vtest(nspec) != 1) {
   MsgBox("Error: Alias is not found or "
   "a targer variable is not DBL scalar");
   return 0;    /* terminates script execution */
}

// Evaluate a desired variable
x = idn(nspec);     /* x is equal to value of a desired variable */

// Assign a value to a desired variable
idn(nspec) = 10;    /* a desired variable is now equal to 10 */

// Increment a desired variable
idn(nspec) += 1;    /* a desired variable is now equal to 11 */
